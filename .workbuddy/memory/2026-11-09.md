- `pick_target` 纵向候选带 = zone 上扩 jump_reach、下扩 dy_tol(150)；带外的怪
  不进决策直接巡逻。签名变为 `(char_box, monsters, range_px, range_h, jump_reach, dy_tol)`。

- 画图验证：真实画面黑屏（过图）没法截，改用「ast 抽 draw_attack_range/_dash

## 挂机失效排查：游戏窗口被最小化（b97d081）
- 症状：用户报「挂机没效果、攻击范围框也不见了」。`/api/stats` 显示
  `window_found:false`、`client_size:[0,0]`、`frame_age_ms` 上万——
  根本抓不到帧，人物框和攻击框都挂在 `overlay_char()`（依赖 char_state.box）上，
  所以一起消失；bot 没有 targets 自然一直「空闲」。
- 实测窗口：`冒险岛怀旧服` UnityWndClass，`IsIconic=1`、rect (-32000,-32000)、
  client 0×0 —— 就是最小化，不是分辨率/选区问题。
- 原代码 bug：`self.error = "窗口未找到或已最小化" if not hwnd else "客户区尺寸异常"`
  **条件写反**，最小化时 hwnd 存在，永远落到「客户区尺寸异常」，看不出真原因。
- 修法：三态分开（无窗口 / 已最小化 / 客户区异常），stats 增 `window_minimized`；
  index.html 角标显示「窗口最小化」且可点击调 `/api/window/focus` 还原，m.html 文案同步。
- `_wait_foreground` 增加 `not IsIconic` 判据：最小化的窗口也能当「前台」，
  原来会把还原失败谎报成「已前置」。
- **权限事实**：游戏进程 `Maplestory_Classic` 以管理员身份运行（读不到 Path=
  高完整性），普通权限的 python 调 `ShowWindow(SW_RESTORE)` 无效（UIPI 拦），
  `SetForegroundWindow` 会成功但窗口照样 minimized。所以网页按钮还原不了时，
  只能手动点任务栏；要自动化就得用管理员身份起服务。

## 按键出口：没 CH9329 就用 SendInput（9c0271d）
- 需求原话：「输入如果检测不到 CH9329 就用 sendkey 的方式」。
- `Sender.__call__` 原本已经会回落 `send_key`，但有一个真 bug：每次按键都同步
  调 `_maybe_retry()` → `find_port()` 挨个串口 probe（每口 0.25s 超时）。
  没小板时按一下卡几百毫秒，走位一顿一顿，看起来就是「软件注入没生效」。
- 改成后台 `hid-retry` 守护线程：0.5s 轮询，5s 起试、失败 ×1.7 退避到 60s，
  连上后自动接管（不用重启服务）。按键路径只做 `send_key`，实测 0ms。
- `send_key` 返回 <1 = SendInput 被拒。常见原因是**游戏以管理员运行、UIPI 拦低权限
  注入**。以前 `>= 1` 只影响返回值、没人看，现在会写 err：
  「软件注入被系统拦下：游戏以管理员身份运行，请用管理员身份启动服务」。
- `describe()` 三态：`硬件 COMx` / `软件注入（未检测到 CH9329）` / `软件注入`。
- 新增根目录 `以管理员启动.bat`（检测非管理员就提示右键提权，不自动弹 UAC）——
  软件注入必须与游戏同级权限，否则一个键都进不去。注意：当前游戏进程
  `Maplestory_Classic` 就是管理员权限，所以无小板时必须走这个 bat。
- `tools/test_sender.py`：把假 hidinput 塞进 sys.modules，monkeypatch `bot.send_key`
  （绝不发真键），15 项断言：无硬件降级、按键最慢 <50ms、扫描只发生在后台、
  掉线回落、注入被拒返回 False。
- 踩坑：服务跑着会自动改写 `webui/bars.json`（auto 标定，窗口没画面时写进脏值
  2049×1152、y2 0.9957）。验证完要 `git checkout -- webui/bars.json` 再提交。
