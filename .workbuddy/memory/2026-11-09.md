## 攻击区域矩形化 + 跳跃攻击（7feb998）
- 判定改为**矩形求交**：`attack_zone(plate, range_px, range_h)` 以身体中心为原点，
  宽 range_px（默认 100）× 高 range_h（默认 120，UI 新增「攻击高度」滑块）；
  怪物框与它有交集才出手——所见即所打，`draw_attack_range` 画的就是这个矩形。
- 头顶的怪：`gap = zone顶 - 怪底 ∈ (0, jump_reach]`（jump_reach 默认 140，
  /api/bot/set 可调、无 UI）→ 按 Alt 跳起来打。**不在这里判攻击**：跳完人物
  （名字牌）升高、区域跟着上移，交上集自然走正常攻击流程。跳跃冷却
  `JUMP_COOLDOWN_MS=900`。正下方一层 / 差太多 → 站住提示「高度够不着」。
- `pick_target` 纵向候选带 = zone 上扩 jump_reach、下扩 dy_tol(150)；带外的怪
  不进决策直接巡逻。签名变为 `(char_box, monsters, range_px, range_h, jump_reach, dy_tol)`。
- `char_body_box` 挪到 bot.py（决策/画图/重叠过滤共用），server 里只剩别名
  `char_body_box = botmod.char_body_box`；test_charbox.py 改为直接 import bot。
- 画图验证：真实画面黑屏（过图）没法截，改用「ast 抽 draw_attack_range/_dash
  源码 + FakeBot」合成帧像素校验，矩形 [611,316..811,436] 逐边吻合。
- 测试：test_bot 56 项（新增 6b 跳/6c 太高巡逻/6d 下方站住）、test_charbox 23 项。

## 攻击方向 front（单体技能只打正前方）(fc177a6)
- 新配置 `range_side`：`both`（默认，左右各 range_px）/ `front`（只朝 face 那侧
  展开 range_px）。`attack_zone(plate, w, h, face=0, side="both")`，**朝向 0 时
  按两侧算**（不知道朝哪别假装知道）。`in_attack_zone` 同步加了 face/side。
- 朝向问题的结论（用户问的）：这游戏读不到朝向，名字牌模板翻转是反字用不了，
  想真读得另采「身体模板」+ flip 镜像做双模板匹配（约 1~2ms/帧，还得加采集 UI）。
  最终选**不判断、只校准**：front 模式每刀前轻点一次目标侧方向键重新对正，
  转身 50 + 等 130ms 塞得进 420ms 攻击冷却，几乎不损攻速。跳前也先对正。
  判据说「记得对」≠「刚确认过」：`calibrated = _t_turn > _t_atk`。
- 判定用 **side**（假设面向目标），绘制用**真实 face**；`_set_status()` 每次都
  把 `self._face` 写进 status["face"]，server 从 snapshot 取。
- 画图：front 时矩形从身体中心单侧展开，标签 `ATK 100x120 ->|<-|?`，**标签挪到
  框外侧**（放在框内会压住人物：标签宽 ~115px > 单侧框 100px）。
- 合成帧校验：两侧 611..811 / 朝右 711..811 / 朝左 611..711 / 未知 611..811。
- `_step(cfg, now=None)` 加了可选假时钟，测试可以精确拨时间。测试 72 项全过。
- 未做：身体模板匹配读朝向（用户暂不需要）；面板不显示朝向数值，只靠框和箭头。
