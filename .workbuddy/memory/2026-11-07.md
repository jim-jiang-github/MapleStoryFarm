## best.pt 接入 WebUI（473 类怪物检测, imgsz 960）
- 导出对比: ONNX CPU 202ms; OpenVINO FP32 CPU 155ms/核显 68ms; INT8(NNCF) 544x960 CPU 69ms; **INT8 384x672 CPU 40ms = 24.7 FPS（采用）**
- 关键优化: 方形 960 输入有 42% 填充浪费 → 矩形 (384,672)/(544,960); FP16 IR 无收益; UHD770 核显有小模型固定开销 68ms 下限
- 模型文件: model_int8_fast_openvino_model(在用) / model_int8_openvino_model(精度优先) / model_544x960, model_384x672 (fp32 底模); 已删 best.onnx
- server.py: 检测线程 + /api/detect/toggle 开关, /stream 自动切换带框画面, stats 增检测字段; UI 加识别按钮+检测统计行+右下角拖拽手柄(grip, pointer capture, 180-720px)
- 实测在线: infer 39-56ms, det_fps ~25, 17-18 目标 (Dark_Stump/Stump/Red_Snail/Master_Robo); res.plot() 标签带类 id 前缀未清理
- tools/quantize_int8.py: 标定帧采集(.image/calib) + NNCF MIXED 量化脚本, 可换底模重跑
- pip 注意: 裸 pip 指向 C:/Python312, 必须 python -m pip 装到工作区 3.13
- 类别过滤功能: server.py 加 det_state["filter"] + /api/detect/filter?name=，draw_boxes() 自绘检测框（替代 res.plot()，标签去掉类 ID 前缀），子串匹配不区分大小写；UI 面板加过滤输入框（防抖 250ms）
- 实测: filter=Snail -> 只剩 Red_Snail×5; filter=Stump -> Stump×14; 推理耗时不变（~37-42ms），过滤是纯软件后处理
- 注意: 游戏被文件管理器遮挡时模型在无关画面上误检 5 个 Red_Snail —— 挂机必须保证游戏窗口不被遮挡
- 预览尺寸解除上限: 拖拽/滑杆最大 1280（applySize 仅用视口宽度-90 兜底，tile 仍有 max-width:100%），.wrap max-width 提到 1440，滑杆量程 180-1280

## 跟踪与锁定层（解决框跳来跳去）
- webui/server.py 新增 IoUTracker: 同类两级匹配（IoU>=0.3 贪心 -> 中心距离兜底 radius=max(80,1.2*(bw+bh)) 处理快速飞行怪），min_hits=3 防闪框, max_age=8 防漏检闪断, EMA 0.6 平滑坐标
- 相机运动补偿: est_camera_shift() 用 cv2.phaseCorrelate(342x192 缩略灰度图, Hanning窗) 估计画面平移, response<0.12 或位移>400px 不补偿; 方向语义已用合成图验证(prev,cur)->内容位移
- 锁定策略 pick_lock: 优先延续旧锁 tid; 新锁要求 hits>=5 且 conf>=0.45, 按面积x置信度; 无合格目标时退选最高conf
- 画面: 每轨迹独立调色板色框 + "#id 类名 conf" 标签, 锁定目标橙红粗框 LOCK 前缀; 面板加"锁定目标"行; stats 加 lock 字段; 关闭识别时清空 tracker
- 离线单测5场景全过(静止ID稳定/快速移动/视角滚动+补偿/锁延续/漏检恢复); 在线实测 lock tid 可连续15s稳定(用户操作时轨迹正常消亡重建)
- 教训: 实例化必须在类定义后(NameError); taskkill 后必须 sleep 再重启
## 瞬现过滤 + 类别投票（防种类跳变）
- IoUTracker 加 streak(连续命中计数, miss 即清零) + confirmed 标志: streak>=min_hits(3) 确认, 确认后不被短期漏检撤销; tracker.pending 统计未确认候选, stats/UI 显示"瞬现过滤 N 个待确认"
- 类别投票 votes{name:[count,cls]}: 轨迹类别=最高票; 未确认跟随多数, 已确认改判需领先 class_margin(6)票; 超60票时票数减半衰减
- 匹配第二级允许跨类别(radius 收紧到 max(40,0.5*(bw+bh))), 保证同一只怪误分类时 ID 不换
- 修 bug: 新建轨迹未加入 used_t 导致首帧被当漏检、streak 清零(确认从第3帧延到第4帧的 off-by-one)
- 单测5场景全过: 闪2帧忽略/第3帧确认/树误判蜗牛2帧保持Dark_Stump/持续10帧真改判/漏检1帧不撤销
## 修复"同一只怪闪不同色框"
- 根因1: 模型 473 类中有 28 组去前缀重名(如 1210100_Pig/9300058_Pig/9300155_Pig), 按类 ID 匹配把同一只怪拆成多条轨迹多色框; 实测真实画面 13 原始框 -> 4 个是重复
- 根因2: 颜色按 tid 取模, 轨迹销毁重建就换色
- 修复: (a)跟踪匹配改按类名; (b)dedupe_dets 同类名 overlap_min>0.6 只留最高conf; (c)class_color(name) 哈希取色, 同种怪永远同色, LOCK 橙色; (d)lost 缓存 resurrect_frames=25 内同类近距重现复用原 tid
- dets 格式改为 (box, name, conf) 三元组, votes 简化为 name->count
- 实测: lock tid 54 连续 12s+ 稳定 conf 0.93-0.94; targets 20+ -> 10-15

## 误检率上升的定量归因（30 帧真实画面 vs best.pt@960 基准）
- 结论: 分辨率是主因(FP32 384x672 召回就掉到 82.9%, 与量化无关), INT8 次之(同尺寸 -3.3%, 多 2.7 框/帧), conf 阈值 0.25 是 FP32 时代调的没跟着改
- FP32 544x960 几乎无损(99.3% recall, 0 extra, 185ms); 中间尺寸 448x800/480x864 收益差已导出但弃用
- 加 UI mask+去重后: INT8 384 conf.35 = recall 83.6%/0.8 extra; INT8 544 conf.35 = 89.6%/0.3
- 改进: DETECT_CONF 0.25->0.35; 新增 MODES fast/accurate 配置表 + /api/detect/mode 热切换(模型缓存复用, 检测线程只启动一次 det_thread_started) + UI 模式按钮与"推理模式"行
- 实测在线: fast 57-60ms/19FPS, accurate 94ms/12FPS
